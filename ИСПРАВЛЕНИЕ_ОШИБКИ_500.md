# 🔧 ИСПРАВЛЕНИЕ ОШИБКИ 500

## Ошибка: "Failed to load resource: the server responded with a status of 500"

Эта ошибка означает, что сервер не может обработать запрос. Обычно это проблема с базой данных.

---

## ⚡ БЫСТРОЕ ИСПРАВЛЕНИЕ (1 минута)

### Шаг 1: Запустите файл
Дважды кликните на файл:
```
fix-prisma.bat
```

Этот скрипт:
- ✅ Сгенерирует Prisma Client
- ✅ Создаст все таблицы в базе данных
- ✅ Применит схему к PostgreSQL

### Шаг 2: Перезапустите сервер
В терминале где запущен сервер:
1. Нажмите `Ctrl+C` чтобы остановить
2. Запустите снова: `npm run dev`

### Шаг 3: Проверьте
Откройте: http://localhost:3000/login

---

## 🔍 ДЕТАЛЬНАЯ ДИАГНОСТИКА

### Причина 1: Таблицы не созданы в базе данных

**Симптомы:**
- Ошибка 500 при регистрации
- В логах: "Table does not exist"

**Решение:**
```bash
# Вариант 1: Через батник
fix-prisma.bat

# Вариант 2: Вручную
npx prisma generate
npx prisma db push
```

**После этого перезапустите сервер!**

---

### Причина 2: Нет роли "Пользователь"

**Симптомы:**
- Ошибка 500 при регистрации
- В логах: "Role not found" или "roleId is required"

**Решение:**
1. Запустите: `node test-simple-db.js`
2. Скрипт автоматически создаст роль
3. Или создайте вручную в Prisma Studio:

```bash
# Откройте Prisma Studio
npx prisma studio

# В браузере откроется интерфейс
# Перейдите в таблицу "roles"
# Добавьте новую роль:
# - name: Пользователь
# - description: Обычный пользователь
```

---

### Причина 3: Prisma Client не сгенерирован

**Симптомы:**
- Ошибка: "Cannot find module '@prisma/client'"
- Ошибка: "PrismaClient is not a constructor"

**Решение:**
```bash
npx prisma generate
```

---

### Причина 4: База данных недоступна

**Симптомы:**
- Долгое ожидание при запросе
- Timeout ошибки
- "Can't reach database server"

**Решение:**
1. Проверьте интернет-соединение
2. Проверьте DATABASE_URL в `.env`:
   ```
   DATABASE_URL="postgresql://..."
   ```
3. Убедитесь что база активна в панели Neon
4. Попробуйте подключиться через браузер:
   ```
   https://console.neon.tech
   ```

## 📝 ПРОВЕРКА ЛОГОВ СЕРВЕРА

### Где смотреть:
Терминал где запущен `npm run dev`

### Что искать:

#### При регистрации должно быть:
```
[REGISTER] Получены данные: { name: '...', email: '...', password: '***' }
[REGISTER] Пароль захеширован
[REGISTER] Пользователь создан: uuid email
[REGISTER] Сессия установлена
```

#### Если видите ошибки:
```
[REGISTER] Ошибка: ...
[REGISTER] Сообщение: ...
[REGISTER] Stack: ...
```

**Типичные ошибки:**

1. **"Table 'User' does not exist"**
   → Запустите `fix-prisma.bat`

2. **"Foreign key constraint failed"**
   → Создайте роль "Пользователь"

3. **"Can't reach database server"**
   → Проверьте DATABASE_URL

4. **"Invalid `prisma.user.create()` invocation"**
   → Проверьте данные запроса

## 📊 ДЕТАЛЬНАЯ ПРОВЕРКА ЧЕРЕЗ DEVTOOLS

### Откройте DevTools (F12):

1. **Вкладка "Console"**
   - Не должно быть красных ошибок
   - Если есть - скопируйте текст ошибки

2. **Вкладка "Network"**
   - Найдите запрос к `/api/auth/register`
   - Кликните на него
   - Перейдите на вкладку "Response"
   - Посмотрите что вернул сервер:

**Успех (201):**
```json
{
  "success": true,
  "user": {
    "id": "...",
    "name": "...",
    "email": "...",
    "role": "Пользователь"
  }
}
```

**Ошибка (500):**
```json
{
  "error": "Ошибка при регистрации. Попробуйте позже.",
  "details": "Table 'User' does not exist in the current database"
}
```

3. **Вкладка "Headers"**
   - Проверьте Request URL: должен быть `http://localhost:3000/api/auth/register`
   - Проверьте Status Code: должен быть 201 (не 500)
