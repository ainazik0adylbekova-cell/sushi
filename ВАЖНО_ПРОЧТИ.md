# 🍣 Суши Жейм - Система оплаты и запуска

## ⚠️ ВАЖНО: Проблема с чеком после оплаты ИСПРАВЛЕНА

### Проблема
После оплаты через Finik появлялась ошибка **ERR_CONNECTION_REFUSED** вместо страницы чека.

### Причина
Сервер не был запущен! После оплаты Finik делает редирект на `http://localhost:3000/payment-success`, но если сервер не работает, появляется ошибка подключения.

### Решение

#### 1. Запустите сервер перед тестированием оплаты

**Простой способ:**
```bash
Двойной клик на START_SERVER.bat
```

**Или вручную:**
```bash
cd "c:\Users\user\Desktop\test sushi\sushi"
npm run dev
```

#### 2. Дождитесь полного запуска
```
✓ Ready in 3s
○ Local:        http://localhost:3000
```

#### 3. Только после этого тестируйте оплату

### Как работает система оплаты

1. **Пользователь оформляет заказ** → `/cart`
2. **Создается платеж** → API `/api/finik/create-payment`
3. **Открывается Finik QR** → Оплата
4. **После оплаты** → Редирект на `/payment-success?orderId=XXX&payment=success`
5. **Показывается чек** → Страница с информацией о заказе

### Что было исправлено

✅ Добавлены параметры `payment=success` и `transactionId` в URL редиректа  
✅ Улучшена страница `/payment-success` для правильной обработки статусов  
✅ API webhook правильно обновляет статус заказа в базе

## 🔐 Настройки (.env)

Убедитесь, что в `.env` указаны:

```env
NEXT_PUBLIC_APP_URL="http://localhost:3000"
FINIK_ENV=beta
FINIK_API_KEY=your-api-key-here
FINIK_ACCOUNT_ID=your-account-id-here
```

**Для продакшена измените:**
```env
NEXT_PUBLIC_APP_URL="https://your-domain.com"
FINIK_ENV=prod
```

## ❓ Частые вопросы

**Q: Почему не показывается чек?**  
A: Убедитесь, что сервер запущен ПЕРЕД оплатой!

**Q: Как проверить, что сервер работает?**  
A: Откройте http://localhost:3000 в браузере

**Q: Ошибка "Cannot connect to database"**  
A: Проверьте DATABASE_URL в .env файле

**Q: Как очистить корзину?**  
A: Данные хранятся в localStorage, очистите кэш браузера
